## 配信データの契約

本番の配信元は `https://ryousyoku.m4sak1.me/`。PDF取得・JSON生成システムは非公開の別リポジトリで運用し、構造化JSONは本番公開済み。

| データ | 用途 |
| --- | --- |
| `data/menus.json` | PDFファイル名・期間・取得日時の一覧 |
| `data/parsed/index.json` | 原本のSHA-256、公開状態、本文への相対パス |
| `data/parsed/YYYYMMDD-YYYYMMDD.json` | 対応する週の構造化本文 |
| `data/skip_periods.json` | 配信側の取得休止期間。個人の欠食記録とは別 |

本文は `schema_version: 1`。日付は `YYYY-MM-DD`、`period.timezone` は `Asia/Tokyo`。各食の `status` は `listed`／`not_listed`／`not_served`。選択肢は固定の `standard`、または順に `A`・`B`。`options[].nutrition` は共通料理を含む食事全体の値。

`MenuRepository` は `ready` と対応する本文パスを確認し、`StructuredMenu.validate` でファイル名・原本ハッシュ・期間・日付の連続性・3食・選択肢・非負で有限の栄養値を検証する。未知のJSON項目は読み飛ばすが、未対応のschema_versionや構造の不整合は受け入れない。

保留・失敗は文字表示と栄養集計に使わない。原本ハッシュが変われば旧キャッシュを削除し、旧版を現在版として使わない。通信失敗時は検証済み保存データに戻せる場合だけ利用し、保存済みであることを表示する。

## 個人記録と朝食デフォルト

選択のキーは `原本SHA-256/日付/食事区分`。食事区分は `breakfast`／`lunch`／`dinner`、値は選択肢IDか `skip`。デフォルトの適用だけでは日別の明示的な記録を作らない。

| 優先順位 | 栄養・文字表示・ウィジェットへの反映 |
| --- | --- |
| 1 | 有効な日別のA/B選択・明示的な欠食 |
| 2 | 選択肢がない食事の固定献立 |
| 3 | 選択式の朝食に対する朝食デフォルト |
| 未確定 | 上記以外の選択式の食事は未選択 |

通知本文は日別選択とは別のルールで、朝食デフォルトがあればその候補と共通料理、なければ両候補を出す。昼夕は全候補を出す。日別の欠食で通知を自動停止しない。

原本改訂後に旧版の記録を新しい原本へ自動移植しない。取得できていない週や旧版など、取得済みデータと対応未確認の記録は統計の集計値と別に扱う。

## 栄養・書き出し

- `summarizeWeek` は日本時間の月曜～日曜で、選択内容／全A試算／全B試算を分ける。
- 各食の選択肢に付いた栄養を1回だけ足す。共通料理を再加算しない。
- 明示的な欠食だけが0。未選択・記載なし・取得不可・栄養値不明を0へ変換しない。
- 栄養素ごとに既知の食数と対象の食数を持ち、部分合計を表示する。合計計算にはBigDecimalを用いる。
- 累計は今日まで。`makeNutritionExport` は未来も `is_future` で区別して保持し、日付が重複する原本を同時に集計しない。
- 書き出しは元PDF識別子、料理・候補・共通料理、選択元、欠食、栄養、未来、不明・未取得・キャッシュの区別を保持する。相談用テキストはデータの意味を説明する導入文付き。

## 統計の数え方

カタログの登場回数は個人の選択に依存しない。対象は今日までの取得済みデータで、全期間／直近30日／直近7日と朝昼夕のフィルターを適用する。

| 指標 | 数え方 |
| --- | --- |
| 料理の登場 | NFKC＋空白除去で同名をまとめ、日付・食事内では1回。A/Bと共通の重複を除く |
| 料理の登場率 | 登場回数 ÷ 対象の掲載食数 |
| 献立の組み合わせ | 候補の料理＋共通料理を集合化して順序を無視。同じ1食内の同一セットは1回 |
| 連続登場 | 異なる登場日が暦上で連続する日数。同日複数回を日数に重ねない |
| 日別の多様さ | その日に掲載された候補込みの異なる料理名の数 |
| 栄養分布 | A/Bをそれぞれ1候補として既知値の平均・最小・最大。不明値は除外 |
| 個人の予定量 | 有効な選択・既定・固定献立を反映し、カタログの回数とは別に集計 |

料理名の別名統合、食材による分類、摂取量や人気の推測は行わない。月別・曜日別の内訳には、収録日数や掲載食数を示す。

## バックアップと端末保存

| 保存先 | 内容 |
| --- | --- |
| `app_prefs` | 表示・テーマ・予測型戻る・朝食デフォルト |
| `meal_selections` | 原本に対応付いた明示的な選択・欠食 |
| `meal_notifications` | 朝昼夕の通知設定、設定の世代、送信済み日付、アイコン |
| アプリのキャッシュ領域 | 取得・検証した構造化JSON、画像等のキャッシュ |

個人バックアップは `format: nitkc-ryousyoku-personal-backup`、version 1。保存日時、朝食デフォルト、選択・欠食を含み、2 MiB・10,000記録まで読み込む。形式・原本識別子・日付・区分・選択値を全件検証し、一部だけを復元しない。

読み込み後に件数等を表示し、追加・統合か置き換えを選ぶ。同一キーの統合はバックアップ側を優先し、朝食デフォルトはどちらでも復元する。書き込み完了後に画面・集計・ウィジェットへ反映する。キャンセルや不正ファイルで既存記録を変更しない。

個人バックアップに、表示設定・通知設定・献立本体・キャッシュは含めない。相談用の栄養JSONとは別形式で、アカウントやサーバー同期は実装していない。

## 通知の予約

AlarmManagerで日付・食事・設定世代を付けて予約し、受信後はWorkManagerがデータを取得・通知する。通常通知は当日・有効な設定世代・オンの食事だけを対象とし、同じ日・食事の送信済み記録で重複を防ぐ。テスト通知は予約や送信済み記録を変更しない。

Android 13以降の通知許可と、Android 12以降の正確なアラームの許可を区別する。時刻の許可がなければ省電力対応の目安の予約へ戻す。再起動・アプリ更新・時計変更・許可付与・アプリ復帰時に再予約する。

当日の候補だけを取得し、別の日で補完しない。データ未取得・確認待ちなら画像/PDFの確認を促し、保存データ利用時は明記する。28種のアイコンは公式SVGをVectorDrawableへ変換したもので、表示中の献立通知は本文・予約を変えず、再通知音なしで更新する。出典とApache-2.0ライセンスはAPK内に同梱する。

## ウィジェットの更新

- `nextMealSlot` が日本時間の8:30／12:50／20:00を境界として対象を決める。20:00以降は翌日の朝食。開始前も次の食事、終了まではその食事を表示する。
- 時間帯は表示しない。通常・省スペースの2レイアウトを高さで選び、料理が収まらなければ省略する。色は端末のライト/ダーク構成に合わせる。
- 受信処理では保存データを描画し、ネットワーク処理はWorkerへ渡す。日付と原本期間を照合し、対象外の献立を表示しない。
- 既知の配信保留・不整合時は対象キャッシュを取り下げる。通信失敗だけを保存済み表示へ戻す。
- 30分ごとの定期処理、終了時刻のアラーム、手動更新、アプリ復帰、個人記録・デフォルト・復元、再起動等で更新する。OSにより遅れる場合がある。
- 置かれている場合だけ更新を予約し、最後のウィジェットを削除すると定期処理とアラームを解除する。
- クリックには対象日を付け、アプリが対応する期間・文字表示の日付を開く。通知と異なり、ウィジェットには日別のA/B・欠食を反映する。

## ビルド・テスト

JDK 17、Android SDK 34、Gradle Wrapperを使用する。

```sh
./gradlew assembleDebug testDebugUnitTest
./gradlew assembleRelease
./gradlew assembleDebug assembleDebugAndroidTest -PmenuBaseUrl=http://127.0.0.1:8765/
adb -s <確認端末> reverse tcp:8765 tcp:8765
```

Windowsの長いパスやOneDrive下等では `-PpreviewBuildDir=<絶対パス>` でアプリモジュールの出力先を変更できる。releaseの取得先は常に本番で、ローカル取得先の上書きはdebugだけに適用する。

`app/src/test/resources/menus/` の既存8週の実データを参照し、日付・朝昼夕、選択・欠食、栄養の欠落と合計、未来除外、重複原本、統計の重複排除、バックアップ検証、ウィジェットの時刻境界等をユニットテストで扱う。`app/src/androidTest/` には画面遷移・設定保存・書き出し/復元・通知・アイコン・統計の操作テストを収録する。テスト用データは製品の献立として同梱しない。

文書のみの更新をリリースさせない場合は、コミットメッセージに `[skip ci]` を付ける。通常のmain/devへのpushは自動リリース対象。
