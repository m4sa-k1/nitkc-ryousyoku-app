# 文字表示・栄養レポート

作業ブランチ: feature/text-menu-nutrition

## アプリの動作

- 設定の「文字で献立を表示」スイッチで、従来の画像表示と文字表示を切り替える。端末内に設定を保存する。
- 過去の献立一覧から週を選び、文字表示内で日付を切り替える。朝昼夕、A/B、共通料理、案内を表示する。
- A/Bの選択と明示的な欠食を端末内に記録し、栄養集計へ反映する。記録は元PDFのハッシュに結び付ける。
- 設定から朝食の既定を「未設定・ごはん（A）・パン等（B）」で保存できる。日別の選択・欠食が優先され、選択肢のない朝食はそのまま使う。Bにはホットケーキ等も含む。
- 朝食の既定は文字表示の選択状態と「選択内容」の栄養集計へ反映する。A/Bでの試算や夕食の選択は変更しない。
- 栄養レポートは「選択内容」を最初に開き、朝食のデフォルトをそのまま反映する。
- 右上の栄養ボタンはスクロール中も表示し、画像モードからも同じ栄養画面へ進める。
- 栄養画面ではカロリー・食塩相当量の週間合計と、4項目の日別グラフ・内訳を表示する。
- 「選択内容」と「Aで試算」「Bで試算」を区別する。献立の予定量であり、実際の摂取量とは扱わない。
- 未選択・原本の空欄・栄養値欠落を0にしない。部分合計は食数を併記し、グラフの棒を薄くする。
- 栄養レポートの「累計・書き出し」では、取得できた全期間のうち今日までを対象に、総カロリー・食塩相当量・たんぱく質・脂質、食数・欠食数・最多登場料理を表示する。未来は累計から除く。
- 累計は献立ベースの予定量であり、実測の摂取量ではない。未選択の食事や未取得の週を集計済みと扱わず、欠けている範囲を示す。
- JSONまたはAI相談用テキストを端末の保存画面から書き出せる。元PDFの識別子、日別の料理・選択・欠食・栄養値、朝食デフォルト、未選択、取得失敗、未来の献立の区別を含める。外食・間食は含まない。
- 書き出しにはAIサービスへの通信を伴わない。AI用テキストは不足情報の確認を促す相談文とデータを含む。
- 設定・栄養レポートの画面内戻るボタンは設けず、端末の戻る操作を使う。A/Bや欠食の選択は色・枠・文言で表し、チェックマークは使わない。
- 過去の献立をタップすると、ポップアップで「文字で表示」「画像で表示」を選ぶ。その選択で設定の既定値を変更しない。
- 設定の「データ確認」から、公開JSONの一覧、表示中の献立の生JSON、端末内の欠食記録を確認できる。献立JSONは表示モデルへの変換前の内容を保持し、文字選択・コピーを可能にする。
- 欠食記録は日付・朝昼夕の一覧と、生の保存JSONを切り替えて参照する。自動の朝食デフォルトやA/B選択を欠食記録に混ぜない。

## 配信データ

既存のdata/menus.jsonに加えて、同じ配信元のdata/parsed/index.jsonと週別JSONを読む。
対応形式はschema_version: 1。readyの週だけを使い、一覧と本文のPDFハッシュ・ファイル名・期間・食事構造を照合する。
確認待ち・非対応形式・検証失敗時は文字表示と栄養集計を保留し、画像から確認できる。
取得成功した構造化データはキャッシュし、通信失敗時の保存済み表示を区別する。

本番のJSON生成・公開はm4sa-k1/m4sak1.meのfeature/structured-menu-extractionブランチ側。
本番へその変更を反映するまでは、新しいJSONは本番ドメインに存在しない。
エミュレーターでは、そのブランチの検証済み実データをローカル配信している。
プレビュー用データを製品APKへ同梱したり、架空の数値を本番表示したりしない。

## 開発確認

JDK 17、Android SDK 34を使用する。

    ./gradlew assembleDebug testDebugUnitTest

ローカル配信を使う場合はdebugビルドだけ取得先を上書きできる。

    ./gradlew assembleDebug assembleDebugAndroidTest -PmenuBaseUrl=http://127.0.0.1:8765/
    adb -s <確認端末> reverse tcp:8765 tcp:8765

Windowsの長い作業パス等では、-PpreviewBuildDir=<作業用の絶対パス>で出力先を指定できる。
debug版のパッケージはcom.m4sak1.ryousyoku.debug。通常版の端末データ・署名と分ける。
release版の取得先は常にhttps://ryousyoku.m4sak1.me/で、ローカル配信の指定は適用しない。

テストには実PDFに対応する全8週のJSONを使用する。これらはテスト専用リソース。
ユニットテストは日別集計、A/Bの独立選択、明示的な欠食、欠落値、週の境界、原本改訂、形式の拒否を確認する。
エミュレーターの操作テストは設定保存、初期画面の朝昼夕の表示範囲、栄養画面への移動・項目切替を確認する。


## 個人記録のバックアップ

設定の「バックアップ・復元」から、欠食・A/B等の明示的な選択記録と朝食のデフォルトをJSONファイルに保存・復元する。端末のファイル選択画面で保存先・読み込み元を選ぶ。献立本体、キャッシュ、表示設定は含まない。栄養レポートの相談用JSONとは別形式。

形式識別子 `nitkc-ryousyoku-personal-backup`、version 1、保存日時（オフセット付き）、breakfast_default、selectionsを持つ。原本SHA-256・日付・食事区分のキーを維持し、PDF改訂時に旧記録を別の原本に適用しない。2 MiB・10,000記録まで。形式・バージョン・日付・選択値等を全件検証し、一部のみの読み込みは行わない。

読み込み後に保存日時と件数を確認し、追加・統合（同一キーはバックアップ優先）か置き換え（全記録を置換）を選ぶ。朝食のデフォルトはどちらでも復元する。キャンセル・検証失敗時は現在の記録を維持する。読込後の確認までは書き換えず、保存完了後に表示・栄養集計へ即時反映する。
